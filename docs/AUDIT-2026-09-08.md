# SMARAN.AI review — 8 September 2026

This continues the previous audit and reviews the current working tree, including
the user's recent Claude changes. It is not a declaration that every platform or
feature is complete. Existing work and user data were preserved.

## Fixes verified in this pass

- Video installation no longer promotes a staging directory after this process
  has activated the live package directory. The activation lock also prevents
  competing status/install threads from swapping directories concurrently.
- A failed staging rename restores the previous live directory. Retired copies
  receive unique names instead of deleting a fixed backup before a replacement.
- A retry preserves a completed staged download and asks for restart. Cleanup
  failure is reported instead of installing over a partly removed directory.
- Windows DLL search directory handles remain alive for the process lifetime.
- The installer checks that an external interpreter matches its Python minor
  version, including resolving that version through the Windows Python launcher.
- Availability checks include all required packages, rather than treating torch
  alone as a complete installation. Import/DLL failures return unavailable.
- Install worker exceptions become a terminal failure instead of leaving the UI
  running indefinitely. Blocking install status work runs in FastAPI's thread pool.
- Download counters accumulate received bytes, not the full size of incomplete
  files. The UI displays the current file percentage and remaining bytes. Overall
  progress remains explicitly estimated; cached packages cannot supply a genuine
  whole-install download percentage from these counters.
- Failed install-start HTTP requests now show an error in Model Hub.
- VS Code delegated runs cannot register a fresh delegator after the parent
  temporarily clears its handler. This closes a recursive delegation bug.

## Scope still requiring evidence

### Independent recheck of subsequent changes

Current source includes an Energy Core redesign and voice-state helpers that
were not present during the earlier audit. Do not recreate these features based
on the older inventory. The current frontend signal/native-speech/status suite
passes 29 tests via `npm run test:unit`. The speech tests require Node's
experimental VM module flag; the script now supplies it. Updated the old
continuous-silence assertion to cover both single-utterance completion and
continuous retry/cancellation explicitly.

Found and fixed a misleading UI/UX skill result: it assigned fixed numerical
scores without inspecting an interface. Results now explicitly identify
guidance only, contain no numerical score, and list evidence needed for an
audit. Missing descriptions now produce actionable validation errors instead
of slicing None. Nine regression cases pass.

Sidebar memory operation messages were never rendered. They are now visible,
memory loading state is set before fetching, fetch failures are reported, the
close button is labelled, and workspace status uses the authenticated fetch
helper. Removed unused imports/props/listeners; frontend lint currently reports
no warnings. Production frontend build passes (17.89 seconds); the build tool
reports a plugin timing advisory. These source/build checks do not verify an
installed Windows or Android release or live deployment.

The hardcoded standalone portfolio generator in main.py has no discovered
caller; its existence alone does not establish that live AI responses use it.
No conclusion of full Genspark/AgentRouter feature parity or successful execution
of every connector/MCP integration is supported by this recheck.

The Windows rebuild was started in `.cache/audit/windows-build`; its result must
be checked before replacing an installed app or distributing an installer.
Real video package installation, a generated video, physical Android speech,
fresh platform packages and deployment verification remain separate acceptance
checks. Earlier September 7 evidence does not verify today's new source changes.

The Experiential repository describes an Apache-2.0 local/BYOK gateway alongside
hosted services. Its source has not been integrated in this pass. Local routing
does not make a paid upstream provider free. Both supplied Drive folders failed
to open through web access, so their contents have not been reviewed.

The existing `backend/app/director` is a video assembly module. The VS Code
delegate is a bounded secondary run using its parent's model. Neither by itself
proves that the requested multi-provider director, task ownership, fallback and
one-prompt website acceptance test have been implemented.
